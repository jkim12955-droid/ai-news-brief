# news-brief

GDELT 에서 한국어 AI 기사를 받아 아침 브리핑과 월요일 리포트를 만든다.
받아오기와 세기는 코드가 하고, 제목을 보고 고르고 묶고 문장을 쓰는 일은 AI 가 한다.
AI 가 내린 판단은 DB 에 남기고 집계는 그 기록으로 하기 때문에, 같은 날을 다시 돌려도 숫자가 흔들리지 않는다.

프로젝트 자리는 `/Users/kimhyojun/Desktop/포트폴리오/ai-news-brief` 다. 아래 명령은 모두 그 안에서 돌린다.

## 언제 쓰나

- 아침 브리핑을 손으로 한 번 더 보고 싶을 때. 깃허브 액션이 매일 아침 9시에 같은 명령을 돌린다.
- 월요일 리포트를 만들 때. 지난주 월요일부터 일요일까지를 정리한다.
- 액션이 실패했을 때. 먼저 `qa` 를 돌려 어디가 어긋났는지 본다.
- 검색어나 키워드를 고친 다음. `/Users/kimhyojun/Desktop/포트폴리오/ai-news-brief/config/keywords.json` 을 손보고 다시 돌려 결과가 어떻게 달라지는지 본다.

## 어떻게 도는가

```
python -m news_brief run                       어제치를 받아 브리핑까지. 전송은 미리보기
python -m news_brief run --date 2026-09-11     날짜를 집어서
python -m news_brief run --no-dry-run          실제로 슬랙에 보낸다
python -m news_brief collect                   받아서 DB 에 넣기만
python -m news_brief qa                        쌓인 자료만 점검
python -m news_brief brief --force             판단부터 다시 해서 브리핑만 새로
python -m news_brief report --week 2026-09-07  그 주 리포트
```

`run` 은 일곱 단계를 이 순서로 밟는다.

1. 수집. 한국 날짜 하루를 UTC 구간으로 바꿔 GDELT DOC 2.0 을 부른다. 5초에 한 번, 한 번에 250건이 상한이라 상한에 걸린 구간은 반으로 쪼개 다시 받는다.
2. 적재 전 점검. 받아 온 것만으로 볼 수 있는 멈춤 조건 다섯 가지를 먼저 본다. 여기서 실패면 DB 에 아무것도 넣지 않고 멈춘다. 날짜가 어긋난 기사는 한 번 들어가면 되돌릴 길이 없어서 넣기 전에 거른다.
3. 적재. `data/news.db` 에 링크를 열쇠로 넣는다. 같은 날을 다시 돌려도 기사는 처음 본 날에 매달려 있다.
4. 판단. 제목만 보고 AI·데이터 소식인지 가리고, 같은 사건끼리 묶고, 새 도구인지 규제인지 정한다. 걸러낸 이유를 함께 남긴다. 그 날 판단이 이미 있으면 그것을 다시 쓴다.
5. 전체 점검. 열한 가지를 본다. 기사가 0건이거나, 쪼개고도 250건에 걸린 구간이 남았거나, GDELT 가 막아 못 받은 구간이 남았거나, 날짜가 어긋난 기사가 수집 건수의 한 할을 넘거나, 판단이 다룬 건수가 DB 건수와 다르면 실패다. 실패면 브리핑을 만들지 않고 실패 알림만 보낸다. 판단을 앞에 둔 덕에 걸러낸 비율도 첫 실행에서 잰다.
6. 브리핑. 한 줄 요약, 어제 기사 수와 최근 이레 평균 대비, 묶음 서넛에서 다섯, 처음 보는 키워드, 규제와 정책 묶음을 마크다운과 슬랙 블록으로 만든다. 묶음 상한은 대표 묶음과 규제 묶음까지 합쳐 세고, 잘라낸 개수는 본문에 한 줄로 적는다.
7. 전송. 기본은 미리보기라 바깥으로 아무것도 나가지 않는다. `--no-dry-run` 을 붙여야 실제로 보낸다. 깃허브 액션에서는 저장소 변수 `SEND_FOR_REAL` 이 `true` 여야 실제로 나가고, 그 전에는 시크릿이 있어도 미리보기다. 노션은 연동 전이라 항상 미리보기다.

날짜를 적지 않으면 어제(한국 날짜)를 쓴다. 아침에 도는 일이라 어제가 기본이다.
`report` 는 날짜를 적지 않으면 지난주 월요일부터 일요일까지를 본다. 같은 주를 다시 돌리면 이미 있는 파일을 덮어쓰지 않고 그 사실을 적는다. 덮어쓰려면 `--force` 를 붙이고, 사람이 적은 코멘트는 어느 쪽이든 새 리포트로 옮겨 붙인다.

### 조용한 날은 두 가지다

브리핑에 "어제는 조용했다" 가 실리는 날은 묶을 것이 없는 날이다. 기사는 모였지만 판단이 다 걸러낸 경우다. 기사가 한 건도 모이지 않은 날은 점검이 수집 건수에서 실패로 막아 브리핑 자체가 만들어지지 않는다. `run` 이 종료 코드 1 로 끝나고 파일도 없으면 그쪽이다.

## 무엇을 보고 판단하나

| 볼 것 | 어디서 | 어떻게 읽나 |
|---|---|---|
| 점검 표 | `qa` 나 `run` 의 표준 출력 | 정상이면 그냥 두고, 주의면 설명을 읽고, 실패면 브리핑이 만들어지지 않았다는 뜻이다 |
| 기사 수와 평균 | 브리핑 둘째 줄 | 최근 이레 평균의 절반도 안 되면 주말이나 연휴인지, 수집이 막혔는지 가른다 |
| 250건 상한 | 수집 직후 출력의 "상한에 걸린 구간" | 남아 있으면 그만큼 기사를 놓쳤다. `max_split_depth` 는 다섯까지만 먹는다. 그보다 크게 적으면 다섯으로 끊고 경고만 남긴다. 다섯에서도 남으면 깊이 대신 검색어를 좁히거나 하루를 반씩 나눠 두 번 돌린다 |
| 막힌 구간 | 같은 자리의 "GDELT 가 막아 받지 못한 구간" | 상한 문제와 다른 일이다. 5초 간격과 세 번 다시 부르기를 다 쓰고도 막힌 것이니, 한동안 쉬었다가 같은 날짜를 다시 돌린다 |
| 묶음 개수 | 브리핑의 묶음 절 | 셋이 안 되면 비슷한 제목을 못 묶었다는 신호다. `judge.similarity_threshold` 를 내려 본다. 반대로 넘칠 때는 "묶음 아홉 개 가운데 다섯 개만 올렸다" 같은 줄이 본문에 붙는다 |
| 처음 보는 키워드 | 브리핑 아래쪽 | 최근 이레에 없다가 어제 나온 말이다. 비어 있는 날이 여러 날 이어지면 관심 키워드 목록이 좁은지 본다. `brief.max_keywords`(기본 여덟)를 넘겨 끊었을 때는 "외 N개" 로 몇 개를 뺐는지 밝힌다 |
| 판단 대조 | 점검 표 | 실패면 판단이 다룬 건수와 DB 건수가 갈렸다는 뜻이다. `--force` 를 붙여 그 날짜를 다시 판단한다 |
| 기록 이어짐 | 점검 표 | 주의가 뜨면 앞선 이레 기록이 DB 에 없다는 뜻이다. 그런 날은 처음 보는 키워드 절을 아예 내지 않는다. 액션에서 이 주의가 이어지면 DB 캐시가 끊긴 것이니 Actions 의 캐시 목록을 본다 |
| 버린 이유 | DB 의 judge 기록 | 살아 있어야 할 기사가 빠졌으면 여기서 이유를 본다. `exclude` 목록이 너무 넓은 경우가 많다. 걸러낸 비율 점검이 같은 신호를 표에 적어 준다 |
| 링크가 맞는지 | 사람이 직접 열어 본다 | 자동 점검에도 링크 대조가 있지만 기본은 꺼져 있다. 실데이터로 돌릴 때 `qa.link_check.enabled` 를 켜면 응답 제목과 기사 제목이 겹치는지까지 본다 |

종료 코드는 셋이다. 0 이면 정상, 1 이면 점검 실패라 산출물을 만들지 않았다, 2 면 설정이나 코드 쪽에서 멈췄다.
깃허브 액션은 0 이 아닌 값을 실패로 표시하고, 실패 알림 단계가 슬랙으로 한 줄 보낸다.

## 어디를 고치나

- 검색어, 요청 간격, 임계값: `/Users/kimhyojun/Desktop/포트폴리오/ai-news-brief/config/settings.json`
- 관심 키워드, 규제와 도구와 제외 낱말: `/Users/kimhyojun/Desktop/포트폴리오/ai-news-brief/config/keywords.json`. 목록 여섯 개마다 바로 위에 `_설명` 이 붙어 있다. 고친 뒤에는 `brief --date 날짜 --force` 로 다시 판단해 본다. 세는 목록에는 한쪽이 다른 쪽을 품는 말을 같이 두지 않는다. 한 기사가 두 번 세어진다
- 파일을 고치지 않고 한 번만 바꿔 볼 때는 환경변수를 쓴다. `NEWS_BRIEF_QUERY`, `NEWS_BRIEF_MAXRECORDS`, `NEWS_BRIEF_BACKEND`, `NEWS_BRIEF_DRY_RUN` 이 있고, 그 밖의 값은 `NEWS_BRIEF_CFG__judge__max_tokens` 처럼 두 밑줄로 자리를 잇는다.
- 비밀값은 설정 파일에 적지 않는다. 슬랙 웹훅은 `SLACK_WEBHOOK_URL`, 노션은 `NOTION_TOKEN` 과 `NOTION_PARENT_PAGE_ID`, 모델 판단은 `ANTHROPIC_API_KEY` 로만 읽는다. 깃허브에서는 저장소 시크릿으로 넣는다.

## 사람이 할 일

- 브리핑에 오른 기사 두어 건은 링크를 열어 제목이 실제 기사와 맞는지 본다. GDELT 는 제목과 링크만 주기 때문에 본문을 보고 고른 것이 아니다.
- 월요일 리포트의 코멘트 자리는 비워 둔다. 이번 주 소식이 일에 어떤 영향이 있는지는 사람이 적는다.
- GDELT 가 모든 매체를 담지 않는다는 점은 리포트에 그대로 적어 둔다. 빠진 매체가 있으면 그 이름을 적어 두면 다음에 판단하기 쉽다.

## 이 스킬이 빌린 것

한 명령으로 부르고 종료 코드로 성공과 실패를 가르는 방식은 같은 포트폴리오의 protein-qa 스킬에서 가져왔다.
모으기는 코드가 하고 요약과 판단만 AI 에 맡기는 구성, 단계를 쪼개 문제 난 단계만 다시 돌리는 방식은 컬리 데일리 브리핑 사례에서 가져왔다.
